# ✅ Copilot Agent Builder Demo：

## 光寶科技｜用 Agent Builder 打造「產品規格查詢助手」

**（Declarative Agent + Knowledge 完整教學 Demo）**

***

## 🎬 Demo 背景鋪陳（45–60 秒｜你開口說）

> 前面我們用了 Chat、Notebook、Pages，  
> 但這些工具有一個共同的限制：**它們只能用公開的網路資訊**。
>
> 在光寶科技的日常工作中，真正有價值的資料是什麼？  
> 是你們的**產品規格書、技術白皮書、內部 SOP、供應鏈報告**——  
> 這些東西 Google 搜不到，Copilot 預設也不知道。
>
> 今天我要示範的是 **Copilot Agent Builder**：  
> 你可以自己建一個「專屬 AI 助手」，  
> **讓它讀你指定的內部文件，只根據這些文件來回答問題。**
>
> 我們的情境是：打造一個**「光寶科技產品規格查詢助手」**，  
> 讓業務、PM、工程師可以隨時問它產品規格、技術參數、應用場景。

***

# 🔹 Step 1：進入 Agent Builder

### 🎯 目的

*   讓學員知道 Agent Builder 在哪裡
*   認識 Declarative Agent 的概念

***

### 🧪 你實際操作

1. 開啟 Microsoft 365 Copilot（m365.cloud.microsoft/chat）
2. 點擊右上角或側邊欄的 **「建立代理程式」**（或搜尋 "Copilot Studio"）
3. 選擇 **「新增代理程式」→「設定代理程式」**
4. 會看到代理程式的設定畫面：名稱、描述、指示、Knowledge

***

### 🗣️ 你可以這樣說（教學語句）

> Agent Builder 讓你不用寫程式，就能做出一個「專屬 AI 助手」。  
> 這個助手跟一般 Copilot Chat 最大的差別是：  
> **你可以決定它「讀什麼」、「怎麼回答」、「不能說什麼」。**  
> 這就是所謂的 **Declarative Agent**——你「宣告」它的能力範圍。

***

# 🔹 Step 2：設定代理程式基本資訊

### 🎯 目的

*   示範如何定義 Agent 的「身份」
*   讓學員理解 Agent Name / Description / Instructions 的作用

***

### 🧪 你實際操作

依序填入以下欄位：

**代理程式名稱：**

```
光寶科技產品規格助手
```

**代理程式描述：**

```
協助查詢光寶科技電源供應器、光電元件、車用電子等產品的技術規格、應用場景與產品比較。
```

**代理程式指示（Instructions）：**

```
你是光寶科技的產品規格查詢助手。你的使用者包含業務人員、產品經理和工程師。

## 你的職責
- 根據 Knowledge 中的產品規格文件，回答使用者的技術問題
- 提供精確的產品參數、規格比較、應用場景建議
- 如果使用者問到產品選型，根據需求條件推薦合適的產品型號

## 回應規則
- **只根據 Knowledge 中的文件回答**，不要自行編造規格數據
- 如果找不到相關資訊，明確告知：「目前 Knowledge 中沒有這項資訊，建議聯繫產品部門確認。」
- 使用繁體中文回答
- 回答時標註資料來源的文件名稱
- 使用結構化格式（表格、條列）呈現規格參數

## 不可以做的事
- 不可以回答與產品規格無關的問題（如公司財務、人事）
- 不可以編造不存在的產品型號或規格
- 不可以提供未經內部核准的報價資訊
```

***

### 👀 你示範給學員看的重點

*   **名稱和描述**：讓使用者一看就知道這個 Agent 能做什麼
*   **Instructions 就是 System Message**：定義 Agent 的角色、能力邊界、回應規則
*   特別強調「**不可以做的事**」——這是企業級 AI 的關鍵

***

### 🗣️ 教學關鍵話術

> 注意看 Instructions 裡面，我不只寫了「要做什麼」，  
> 還寫了「**不可以做什麼**」。  
> 這在企業環境裡非常重要——  
> 你不會想讓一個產品助手去回答公司的財務問題或亂報價。

> ⚠️ **轉檔注意事項**：用 Excel 開啟 CSV 時，請確認編碼選擇 **UTF-8**，避免中文亂碼。

### 🧪 你實際操作（加入 Knowledge）

1. 在 Agent Builder 設定頁面，找到 **「Knowledge」** 區塊
2. 點擊 **「新增知識」**
3. 選擇來源類型：
   *   **SharePoint** → 選擇存放產品規格 Excel 文件的站台或資料夾
   *   **上傳檔案** → 直接上傳準備好的 `.xlsx` 檔案
4. 依序加入上述 3 個 Excel 檔案
5. 等待文件處理完成（通常幾秒到幾分鐘）

***

### 👀 你示範給學員看的重點

*   Knowledge 支援多種檔案格式：**Word、PDF、PowerPoint、Excel、文字檔**
*   可以從 **SharePoint、OneDrive** 直接選取，也可以上傳
*   Agent 只會根據這些文件來回答——**不會去 Web 搜尋，不會自己編造**
*   這就是 **Grounding（接地）**：AI 的回答被「綁定」在你提供的資料上

***

### 🗣️ 教學關鍵話術（非常重要）

> 這一步是整個 Agent Builder 最關鍵的地方。  
> 你加進去的文件，就是這個 Agent 的「大腦」。  
> **它知道的，就是你餵給它的；你沒餵的，它就不會亂講。**
>
> 這跟一般的 ChatGPT 完全不同——  
> ChatGPT 可能會根據訓練資料「猜」一個答案，  
> 但這個 Agent **只會從你的文件裡找答案**。  
> 找不到？它會老實告訴你「我不知道」。

> | ✅ 模糊需求 | #4 只說「要省電」 | 列出選項，引導客戶追問 |
> | 🚫 超出範圍 | #5 公司營收 | 拒答，引導正確管道 |
> | 🚫 敏感資訊 | #6 要求報價 | 拒答，引導聯繫業務 |
> | 🚫 不存在產品 | #7 編造型號 | 不編造，列出已知型號 |
> | ✅ 複合條件 | #8 液冷+4000W+CAN | 精準匹配唯一符合的產品 |
> | 🛡️ Prompt Injection | #9 試圖覆寫指令 | 完全拒絕，維持角色 |
> | ✅ 英文提問 | #10 英文問規格 | 用繁體中文回答（遵守 Instructions） |
> | ✅ FAQ 查詢 | #11 保固與 RMA | 從 FAQ 文件擷取，含流程步驟 |
> | ⚠️ 知識邊界 | #12 高海拔降額 | 誠實說「資料不足」，給已知資訊 |

> **重點：一個好的 Agent，不只要「答對」，更要在該拒絕的時候拒絕、該承認不知道的時候承認。**
